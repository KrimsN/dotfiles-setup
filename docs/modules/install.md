# install.sh

Единая точка входа (корень репозитория), связывает все модули. Два
режима запуска:

- **`curl | bash`** — у скрипта нет собственного пути на диске (stdin),
  поэтому сначала бутстрапит `git`/`curl` напрямую через пакетный
  менеджер (единственное намеренное дублирование логики определения
  дистрибутива в проекте — `scripts/lib/os-detect.sh` ещё не скачан,
  использовать неоткуда), затем клонирует репозиторий в
  `~/.local/share/knrc` (переопределяется `DOTFILES_DIR`) и
  подключает все `scripts/lib/*` и `modules/*` из свежего клона.
- **`./install.sh` из уже склонированного репозитория** — определяет это
  по наличию `modules/` рядом с `${BASH_SOURCE[0]}`, клонирование не
  требуется.

Интерактивное меню (схема из "Механизм конфигурации" в CLAUDE.md): вопрос
"всё или выбрать вручную" через `/dev/tty`, при выборе вручную — по
вопросу на каждый модуль. `--yes`/`NONINTERACTIVE=1` пропускают меню
(ставится всё). `DOTFILES_MODULES="base zsh ..."` задаёт список модулей
без интерактива вообще (для автоматизации/CI) — сами модули внутри себя
независимо читают свои собственные env-переопределения
(`ZSH_DEFAULT_SHELL`, `DOCKER_ADD_USER_TO_GROUP`), install.sh их не
трогает и не дублирует.

## Лаунчер `knrc`

Помимо модулей `install.sh` всегда ставит команду `knrc`
(`install_sh::_install_launcher`) — тонкий шим в `~/.local/bin/knrc`,
делающий `exec` на `scripts/knrc.sh` в каталоге репозитория. Не модуль, а
часть ядра: диагностика должна быть на машине при любом наборе выбранных
модулей. Перед этим вызывается `localbin::ensure_path`, чтобы
`~/.local/bin` оказался в PATH (см.
[localbin.md](localbin.md)). Подчиняется `DRY_RUN`. Обоснование схемы и
сравнение с альтернативами (`install.sh doctor`, голый
`scripts/doctor.sh`) — в [doctor.md](doctor.md).

Список модулей `KNRC_ALL_MODULES` вынесен в `scripts/lib/modules.sh` и
подключается в `install_sh::main` — в начале файла его определить
нельзя, при `curl | bash` репозитория ещё нет (см.
[modules-list.md](modules-list.md)).

## `--dry-run` / `DRY_RUN=1`

Перехват на уровне трёх общих точек мутации, через которые проходят все
модули, а не на уровне install.sh или отдельных модулей:

- `os::pkg_update` / `os::pkg_install` / `os::pkg_try_install`
  (`scripts/lib/os-detect.sh`) — вместо `apt-get`/`dnf`/`yum` только
  логируют список пакетов;
- `rcfile::upsert_block` (`scripts/lib/rcfile.sh`) — не трогает rc-файл,
  только логирует, какой блок обновил бы;
- `github_release::install` (`scripts/lib/github-release.sh`) — не
  скачивает и не ставит бинарник, только логирует, что поставил бы.

Это покрывает подавляющее большинство реальных изменений на диске/в
системе, но не 100% — команды, которые модуль вызывает напрямую в обход
этих трёх точек (например `chsh`, `usermod -aG docker`, установщики
сторонних проектов вроде oh-my-zsh/TPM/rustup-подобных `curl | sh`),
dry-run не перехватывает. Считать честным приближением, а не полной
симуляцией состояния системы (в отличие от `chezmoi diff`).

## Лог последнего прогона: `~/.knrc.log`

Каждый запуск `install.sh` дописывает одну строку через EXIT-трап
(`install_sh::_write_log`) — время, режим (`install`/`dry-run`), список
модулей, дистрибутив и результат (`ok` или `fail(exit=N)`). Пишется даже
при ошибке (трап срабатывает на любом выходе, включая ранний выход из-за
`set -e`), защищено от `set -u` дефолтами по всем полям и не роняет уже
завершившийся скрипт, если запись в файл не удалась (`|| true`).

## Реальные баги, пойманные при тестировании

- Вывод `apt-get`/`dnf install` внутри бутстрапа не был перенаправлен в
  stderr, а функция клонирования репозитория вызывается через `$(...)`
  — весь этот вывод утекал в переменную с путём к репозиторию, ломая
  `source` дальше ("File name too long"). Исправлено оборачиванием в
  `{ ... } >&2`.
- На CentOS Stream `dnf install curl` конфликтует с предустановленным
  `curl-minimal` без `--allowerasing` — без флага падала вся транзакция
  бутстрапа (git тоже не ставился).

**Тестирование**: end-to-end — холодный `curl | bash` без
предустановленных git/curl на Ubuntu 24.04, Fedora (актуальная) и
CentOS Stream 9 (все три реально бутстрапили git/curl с нуля), плюс
полный прогон всех модулей одной командой на Ubuntu 24.04 — все
проверены на PATH.
