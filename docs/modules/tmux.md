# modules/tmux.sh

Устанавливает tmux (`os::pkg_install`), зависимости для буфера обмена
(`xclip`, `wl-clipboard` — см. ниже), TPM (git clone в
`~/.tmux/plugins/tpm`), пишет `~/.tmux.conf` из `config/tmux.conf` (та же
схема бэкапа через `cmp`, что и у zsh.sh), ставит плагины
`tmux-resurrect`, `tmux-continuum` и `tmux-yank` через headless
`tpm/bin/install_plugins` — для этого нужен хотя бы один запущенный
tmux-сервер с загруженным конфигом (иначе TPM не знает свой путь),
поэтому модуль поднимает временную detached-сессию
`_dotfiles_tpm_bootstrap`, ждёт секунду (строка `run -b` в tmux.conf
асинхронна) и закрывает её после установки плагинов.

Требует `scripts/lib/os-detect.sh`, `scripts/lib/epel.sh` и
`scripts/lib/rcfile.sh` (`source` перед этим модулем).

## Зависимости tmux-yank: xclip / wl-clipboard

`tmux-yank` копирует выделение из copy-mode в системный буфер обмена, но
сам не умеет писать в него — нужен внешний CLI: `xclip` (X11) или
`wl-copy` из пакета `wl-clipboard` (Wayland). Имя пакета одинаковое в
`apt` и `dnf`/`yum` в обоих случаях, так что ветвления по `OS_FAMILY` не
требуется — но ставим их через `os::pkg_try_install` (как `fd-find`/`bat`
и т.п. в `modules/cli-tools.sh`), а не через `os::pkg_install`, потому что
`wl-clipboard` может отсутствовать в части rhel-репозиториев (например
старый CentOS без нужного EPEL-пакета); неудача одного пакета не должна
ронять установку. `epel::ensure` вызывается первым — на debian-семействе
это no-op, на rhel включает EPEL, где живёт часть этих пакетов.

## Содержимое config/tmux.conf

(дополнено 2026-08-24, помимо `mouse on`, который был с самого начала):
`history-limit 50000`, `escape-time 0` (без задержки после Esc — важно
для vim/nvim внутри tmux), `renumber-windows on`, `focus-events on`,
`default-terminal 'tmux-256color'` + `terminal-overrides` для true-color;
удобные сплиты `|`/`-` (сохраняют `pane_current_path`, заменяют дефолтные
`%`/`"`), `prefix + r` — reload конфига без выхода из tmux; кастомный
status-bar (имя сессии, список окон, дата/время, hostname) вместо
дефолтного минималистичного. Vi-style keys в copy-mode осознанно не
добавлены — пользователь их не запрашивал.

`@resurrect-strategy-nvim 'session'` (добавлено 2026-08-25): без этой
опции `tmux-resurrect` восстанавливает только окна и рабочие директории,
но не открытые в nvim файлы — с ней используется встроенный механизм
сессий Vim/Neovim, и nvim восстанавливается с теми же открытыми буферами.

## Поведение по умолчанию (зафиксировано пользователем)

Голый `tmux` без аргументов подключается к уже существующей сессии, если
она есть, иначе создаёт новую; с явными аргументами (`tmux new -s foo` и
т.п.) ведёт себя как обычно. Реализовано shell-функцией в
`config/tmux-autoattach.sh`, которая ставится в
`~/.config/knrc/tmux-autoattach.sh` и подключается из
`~/.zshrc` (условная строка уже зашита в `config/zshrc` — работает
независимо от порядка запуска zsh.sh/tmux.sh) и из `~/.bashrc` через
`rcfile::upsert_block` (т.к. `.bashrc` не управляется целиком).

**Тестирование**: end-to-end в контейнере Ubuntu 24.04: установка,
двойной запуск (идемпотентность — TPM/пакет не переустанавливаются,
`.bashrc`-блок не дублируется), и поведенческая проверка под реальным pty
(`script`) — bare `tmux` подключается к существующей сессии вместо
создания новой, а `tmux new -s <name>` по-прежнему создаёт отдельную
сессию.

## Точка расширения: `~/.tmux.conf.local`

`~/.tmux.conf` перезаписывается install.sh при каждом запуске (с
бэкапом, но всё равно) — свои правки в нём не переживут повторную
установку. Публичный контракт: `config/tmux.conf` подключает
`~/.tmux.conf.local`, если он существует, через `if-shell '[ -f
~/.tmux.conf.local ]' 'source-file ~/.tmux.conf.local'` (условный
`source-file` в самом tmux появился только в 3.0, поэтому используется
`if-shell`, а не прямой `source-file`). Строка подключения вставлена
**перед** инициализацией TPM (`run -b '~/.tmux/plugins/tpm/tpm'`) — та
обязана оставаться последней строкой файла (требование самого TPM), так
что новые точки расширения тоже нужно вставлять до неё, а не после.
`tmux::create_local_file` (вызывается из `tmux::install` сразу после
`tmux::write_config`) создаёт `~/.tmux.conf.local` с поясняющим
комментарием, если его ещё нет — но **только если нет**: при повторном
запуске install.sh существующий файл не трогает и не перезаписывает, так
что пользовательские правки внутри него переживают любое число
переустановок. Игнорируется git'ом через общий паттерн `*.local` в
`.gitignore`.
