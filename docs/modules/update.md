# knrc update

Обновление уже установленного `.knrc` до последней версии из репозитория.
До появления этой команды установленной утилитой `knrc` было нельзя
обновить саму себя — только вручную зайти в `~/.local/share/knrc` и
сделать `git pull`.

Реализация: [`scripts/update.sh`](../../scripts/update.sh) (обновление),
[`scripts/knrc.sh`](../../scripts/knrc.sh) (CLI-диспетчер).

Способ вызова — тот же, что у `doctor` и `uninstall` (см.
[doctor.md](doctor.md)): одна ветка `case` в `scripts/knrc.sh` и один
файл `scripts/update.sh` с публичной функцией `update::run`.

```bash
knrc update --dry-run   # показать входящие коммиты, ничего не менять
knrc update              # обновить клон и перезапустить install.sh
knrc update --yes        # то же, но без интерактивных вопросов
                          # install.sh (--yes уходит в install.sh как есть)
```

Из клона то же самое доступно как `bash scripts/knrc.sh update`, без
установки лаунчера.

## Что делает `update` и почему именно так

Два шага, оба должны быть безопасны сами по себе:

1. **`git pull --ff-only` в `$DOTFILES_DIR`** (обычно
   `~/.local/share/knrc`). `--ff-only`, а не `--rebase`/обычный merge —
   у установленного клона не должно быть локальной истории, разошедшейся
   с origin; если она разошлась (кто-то руками коммитил в этот каталог),
   `update` останавливается с понятной ошибкой вместо того, чтобы молча
   мержить.
2. **Перезапуск `install.sh`** — единственный способ подтянуть новые
   модули так же, как при первой установке, не заводя для этого
   отдельную процедуру диффа модулей. Все аргументы `update`, кроме
   `--dry-run`, уходят в `install.sh` как есть (`--yes`,
   `DOTFILES_MODULES=...`), поэтому `knrc update --yes` ведёт себя
   предсказуемо — так же, как `knrc install --yes` после `git pull`
   руками.

Если рабочая копия в `$DOTFILES_DIR` грязная (`git status --porcelain`
не пуст), `update` отказывается что-либо делать: `--ff-only` всё равно
не сработает при расхождении, а обновлять поверх незакоммиченных правок
пользователя — способ незаметно их потерять. Сообщение об ошибке
предлагает `git stash` или переустановку.

## `--dry-run`

Делает `git fetch` (сеть, но не меняет рабочую копию) и печатает список
коммитов `HEAD..@{upstream}`, если они есть. Перезапуск `install.sh` в
этом режиме не происходит — только сообщение, что он произошёл бы.

## Код возврата

`0` — обновлено (или уже была последняя версия); `1` — `git pull` не
удался (грязное дерево, разошедшаяся история, нет сети); `2` — ошибка
аргументов.
