# modules/git-config.sh

Настраивает `~/.gitconfig`: pager (delta), редактор, разумные дефолты
самого git и глобальный gitignore. Публичная точка входа —
`git_config::install`.

До появления этого модуля `delta` ставился `modules/cli-tools.sh`, но
нигде не подключался: бинарник лежал без дела, а `git diff` шёл через
дефолтный pager. `~/.gitconfig` проект не трогал вообще.

## Почему `git config`, а не копирование файла

Все ключи выставляются через `git config --global <key> <value>`.
Копирование готового `~/.gitconfig` затёрло бы собственные настройки
пользователя (в первую очередь `user.name`/`user.email`), а
`git config` идемпотентен по природе: повторный прогон перезаписывает
те же ключи теми же значениями и не плодит дубликатов в файле
(проверено вторым прогоном в контейнере — см. "Тестирование").

## Что выставляется

Безусловно:

| Ключ | Значение |
|---|---|
| `init.defaultBranch` | `master` |
| `pull.rebase` | `true` |
| `push.autoSetupRemote` | `true` |
| `rerere.enabled` | `true` |
| `diff.algorithm` | `histogram` |
| `core.excludesFile` | `~/.config/knrc/gitignore_global` |

Только если `delta` есть в PATH (`command -v`):

| Ключ | Значение |
|---|---|
| `core.pager` | `delta` |
| `interactive.diffFilter` | `delta --color-only` |
| `delta.navigate` | `true` |
| `delta.line-numbers` | `true` |
| `merge.conflictStyle` | `zdiff3` |

Только если `nvim` есть в PATH: `core.editor = nvim`.

**Guard'ы обязательны**, а не косметика: модули `cli-tools` и `nvim`
можно не выбрать при установке, а `core.pager`, указывающий на
несуществующий бинарник, ломает вообще любой `git diff`, а не только
красивый вывод. Тот же приём применяется в `config/aliases.sh` для
bat/eza.

## Глобальный gitignore

Файл живёт в репозитории как `config/gitignore_global` и копируется в
`~/.config/knrc/gitignore_global` — тем же механизмом, каким
`modules/aliases.sh` кладёт свой снипет. Содержимое: артефакты
редакторов (vim swap, `.vscode/`, `.idea/`), артефакты ОС
(`.DS_Store`, `Thumbs.db`), локальные секреты (`.env`, `*.pem`).

В `~/.gitconfig` путь пишется в форме `~/...`, а не абсолютным: git
сам раскрывает `~/` в значении `core.excludesFile`, а такой конфиг
переносим между машинами с разными `$HOME`.

## user.name / user.email

Единственное, что нельзя выставить за пользователя. Спрашивается
интерактивно через `read ... < /dev/tty` (не через stdin — при
`curl ... | bash` stdin занят телом скрипта, см. CLAUDE.md, раздел
"Механизм конфигурации"). Пустой ответ = пропустить.

Уже заполненное значение не перезаписывается и не переспрашивается
(проверка `git config --global --get`) — благодаря этому повторный
прогон на настроенной машине проходит молча. При `NONINTERACTIVE=1`
или недоступном `/dev/tty` вопрос пропускается без падения.

## Реальные баги, найденные при тестировании

- **`[ -r /dev/tty ]` — недостаточная проверка терминала.** В
  контейнере без выделенного терминала (`docker run` без `-t`, CI)
  файл `/dev/tty` существует и проходит проверку `-r`, но открытие
  падает с `No such device or address`; в лог сыпались две строки
  ошибки на каждый прогон. Исправлено функцией
  `git_config::_tty_available`, которая пробует реально открыть
  устройство (`{ : < /dev/tty; } 2>/dev/null`). Тот же паттерн
  проверки в `install.sh::_selected_modules` даёт такую же диагностику
  — там она пока не исправлена, но и не мешает (ошибка печатается один
  раз, вопрос корректно пропускается).

## Тестирование

`base,cli-tools,git-config` на Ubuntu 24.04 через
`.claude/skills/test-module/`, два прогона в одном контейнере.
Проверено:

- оба прогона проходят без ошибок, `~/.gitconfig` после второго
  прогона не содержит дубликатов ключей — идемпотентность;
- `git diff` в тестовом репозитории работает через настроенный pager;
- `.env` игнорируется благодаря `core.excludesFile`;
- guard на `delta`: при запуске `git-config` без `cli-tools` pager не
  настраивается, модуль отрабатывает с предупреждением;
- guard на `nvim`: с заглушкой `nvim` в PATH выставляется
  `core.editor`, без неё ключ не трогается;
- заранее выставленный `user.name` не перезаписывается;
- под настоящим pty (`script -qec`) вопросы про `user.name`/`user.email`
  реально задаются, а введённые ответы попадают в `~/.gitconfig`.
