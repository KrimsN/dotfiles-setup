# scripts/lib/rcfile.sh

Общая утилита `rcfile::upsert_block <file> <marker> <content>`: идемпотентно
вставляет/обновляет маркированный блок (`# >>> knrc:<marker> >>>`
/ `# <<< ... <<<`) в rc-файле, не трогая остальное содержимое. Нужна для
файлов, которыми управляем частично (например `~/.bashrc`), в отличие от
`~/.zshrc`, который zsh.sh пишет целиком из шаблона.

Парная `rcfile::remove_block <file> <marker>` удаляет ранее вставленный
блок; отсутствие файла или самого блока не считается ошибкой. Появилась
при переименовании маркера `python-tools-path` → `localbin-path` (см.
[localbin.md](localbin.md)): на уже настроенных машинах старый блок
иначе остался бы в `~/.bashrc` и сорсил бы тот же `path.sh` второй раз.
Она же — основа отката rc-блоков в `knrc uninstall` (см.
[uninstall.md](uninstall.md)).

## Пустая строка перед блоком (2026-08-25)

`upsert_block` дописывает перед блоком пустую строку — чтобы блок
визуально отделялся от остального содержимого rc-файла. Изначально
`remove_block` снимал только сам блок, и эта строка оставалась.

Заметно это стало с приходом `knrc uninstall`
([uninstall.md](uninstall.md)): он снимает из `~/.bashrc` сразу три
блока (`aliases`, `tmux-autoattach`, `localbin-path`), то есть оставлял
после себя три пустые строки, а файл, который откат обязан вернуть к
исходному виду, к нему не возвращался. Повторные циклы
install/uninstall копили пустые строки дальше.

Теперь `remove_block` снимает вместе с блоком ровно **одну** пустую
строку непосредственно перед ним. Подряд идущие пустые строки самого
пользователя при этом сохраняются: awk придерживает только последнюю
пустую строку и выбрасывает её, лишь если сразу за ней идёт наш
`begin`-маркер, иначе печатает как есть.

Проверено: после `upsert(a) → upsert(b) → remove(b) → remove(a)` файл
побайтово совпадает с исходным, включая пользовательские пустые строки
внутри.
